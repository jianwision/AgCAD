# 为 LLM 建模设计的 device–host 传输策略

目标是减少阻塞式往返，同时控制字节数。下面明确区分已实现与后续设计。

## 已实现：一个结果包

```text
[80-word header / 64 probes][bounded triangle capacity][RGBA preview]
```

header 的第 0/1/2 个 word 分别为三角形数量、域边界内部采样数和非有限值数量；
第 16–79 个 word 保存 64 个 float 样本的 bits。每个三角形 9 个 word，
每个像素一个 RGBA word。完整场始终在显存中。

采样、提取、渲染、探针收集和锁页主存 DtoH 在同一 stream 排队，
CPU 最后统一解释结果。无需先下载计数、决定长度、再发起第二次下载。
代价是空闲容量也被复制；报告保留实际字节数，溢出则显式失败。

## 后续设计一：合并语义编辑

LLM 一次输出一组参数变更、几何操作和测量要求。宿主消除同一参数的重复修改，
按依赖关系提交整批 GPU 工作，再返回一份摘要。把每个小动作一次工具调用，
改为每轮设计意图一次提交。这需要持久宿主，当前 CLI 每次只执行一个模型。

## 后续设计二：网格留在显存，到导出时再读回

让几何 DAG、场缓存、mesh buffer 常驻显存。参数变化只上传增量；
普通编辑只读回小型状态包。通过 CUDA/图形 API 互操作显示 GPU texture/buffer，
用户按“导出”时才下载完整网格。
当前 HTML 是导出网格的离线查看器，不属于 CUDA 图形互操作，PNG 仍会读回。

## 后续设计三：按预算选择容量读回或精确读回

| 方式 | Host 依赖阶段 | 数据量 |
|---|---:|---|
| 固定容量包，本 demo 已实现 | 1 | 包含空闲槽位 |
| 先取摘要，再取精确结果 | 2 | 只传有效几何 |

近似比较多传字节 `P / 带宽 B` 与额外等待延迟 `L`。
如果 `P/B < L`，容量包可能值得；反之优先精确传输。
实际还要计入锁页分配、调度和链路争用，少往返不保证总时间更低。
连续编辑可用上次三角形数量预测容量并留余量；溢出后扩容重算。

## 后续设计四：GPU 先归约验收摘要

把包围盒、非有限值计数、越界数、体积和极值归约为固定长度摘要。
CPU 保留来自需求或独立公式的预期，并抽查空间位置。
摘要是诊断证据，不是任意形状正确性的证明。
本 demo 已实现边界/非有限值归约和探针；完整网格拓扑仍由 CPU 验证。

## 后续设计五：异步双缓冲与脏区

使用两个设备结果包、两个锁页主存包。CPU 导出上一版时，GPU 计算下一版，
只在消费结果或复用缓冲区时等待相应 event。
用带版本号的空间块记录脏区，只重算受影响块及其邻接边界。
预览只传变化图块或低分辨率图，最终导出保持完整精度。

## 后续设计六：缓存编译结果和执行图

按代码、编译选项、Toolkit 版本和目标架构对 PTX 做内容寻址缓存。
参数变化复用模块，代码变化才编译。固定流程用 CUDA Graph replay 降低提交成本。
这些策略降低编译/launch 开销，本身不减少 PCIe 数据字节数。
本 demo 的首次 NVRTC 编译时间明显高于几何 kernels，值得优先优化。

## 后续设计七：支持 GDS 的环境中分块流式建模

对大型点云/体素建立空间块索引，经受支持的 cuFile 路径送入 GPU。
按视锥或脏区请求工作集，用双缓冲重叠 I/O 与计算；也可研究 GPU 打包导出格式。
CPU 仍负责控制/提交，“绕过 CPU bounce buffer”不等于“没有 CPU”。
本机为 Windows，没有实现或实测 GDS。Linux 上也必须验证 GPU、拓扑、
文件系统和实际直通路径；兼容模式回退到主存不能算作直通。
